# Tududi tags

Some Tududi versions call tags **labels**. Use the installation's Swagger terms
and identifiers while describing them to the user as tags unless the existing
catalog clearly uses another convention.

Before writing, read the available tag catalog and the target task's assigned
tags. Choose no more than three additions that describe durable facets of the
task, such as its project, domain, or work type. The limit applies to additions
for this operation, not the task's final total.

Reuse an existing semantic match before creating one. Compare normalized case,
spacing, punctuation, singular/plural forms, and established naming patterns;
do not create a synonym merely to prefer different wording. When no relevant
match exists, create the missing tag as part of the authorized task operation.

Preserve all existing tags. Confirm whether the installed assignment endpoint
appends or replaces the collection and submit the complete intended identifier
set when necessary. Re-read the task after assignment. On a partial failure,
retain the task and successful tags, report the remaining tag names and task
UID, and inspect state before retrying.
